Reverse-engineering the vendor SDK for the BYS-brand USB lottery betslip scanner/printer (the OMR scanner on the [[reference_lotto_pos_terminal]] POS terminals). Location: `/mnt/c/Repos/gitlab/OMR/` — `lib64/` (DLLs+configs), `BSdriver/` + `BSdriver_x64/` (2012 Windows kernel USB driver BYSUSB.sys).

**What it is:** all native x86-64 Windows C/C++ DLLs, no .NET, no visible obfuscation.
- `lib64/LScannerSDK.dll` — main SDK, the integration target (demo calls this).
- `lib64/lib/*.dll` — processing chain: `decomr.dll` (OMR decode), `dec417.dll`/`LinearBarDecode.dll`/`QRDecode.dll` (PDF417/1D/QR), `ImageFormatTrans`/`ImageZoom`/`PrunedRotatePic`/`bitmap` (image prep), `ScanPrnDevLib`/`BsUSBInt` (device+USB), `SimpleLogModule`.
- `lib64/bin/LScannerSDKDemo.exe` — vendor reference app = live example of correct call sequence.
- Configs plain-text (Chinese comments): `conf/LScannerConfig.ini`, `lib/DecodeCfg.ini`, `lib/ImgConfig.ini`, `lib/FormatFile.txt` (betslip `{1001}` mark-grid layout).

**Key finding — the control surface:** `LScannerSDK.dll` exports 31 clean undecorated C functions (easy to bind). Lifecycle: `SInit`/`SStart`/`SStop`/`ScannerIsReady`/`ScanIsComplete`. Scan/read: `SRecognizeItem`/`SGetTicketInfo`/`SGetOriginImage(Size)`/`SQueryCapability`. Device: `SGetHWInformation`/`SGetBrandDpi`/`SGetScanDpi`/`SGetSWVersion`/`SAdjustSensibility`/`SPrintBrandImage`. Low-level: `LSSendCommand`/`LSQueryStatus`/`LSReceiveInfo`/`LSCalibrateSensor`/`LSUpgradeFirmware`/`LSRollBack`. Errors/config: `SGetLastError(Code|Str)`, `GetConfigFile*`/`WriteConfigFile*`.

**Tool:** REA (github.com/morluto/rea) — MIT, Node 22+ MCP server/CLI that drives Ghidra/IDA/Hopper. Legit "software you own" RE. Can be cloned into `/mnt/c/Repos/gitlab/OMR`. Needs a decompiler engine installed (Ghidra free).

**Two forks for end state (user to pick):**
- (A) **API-binding route** — script/drive existing DLLs from our stack on Windows. Recover signatures by tracing LScannerSDKDemo.exe + disassembling export prologues. Faster. Runs on Windows POS box (driver is Windows-only).
- (B) **Vendor-independent reimplementation** — full decompile of decomr/dec417 decode algos + BsUSBInt USB wire protocol + FormatFile grid format, for Linux/server-side decoding. Bigger effort.

### Gotchas learned today
- Running `powershell.exe -File x.ps1` from WSL with hidden child processes hangs the bash pipe (children inherit stdout) → wrap in `timeout N … < /dev/null` and read log files; `powershell.exe -Command "…"` with `Where-Object { $_… }` sometimes produced no output at all from WSL → prefer a temp `.ps1` file.
- `Get-NetFirewallRule` needs elevation ("Access is denied") — trust the installer transcript.
- SDK log volume: our old polling of SGetTicketInfo wrote ~20 MB/day of `Get decode result failed` spam; the callback model logs only per scan. The SDK rotates at ~20 MB (`_000`, `_001`, …).
- Never auto-dismiss SDK dialogs; never kill the service during the ~1 s eject; killing it idle is safe (scan thread is in 100 ms timed USB polls).
- REA MCP: first Ghidra query on a binary takes 2–3 min (moved to background task), then instant; `search_strings` → `xrefs` → `resolve_containing_procedure` → `procedure_pseudo_code`/`procedure_assembly` is the workflow; `find_xrefs_to_name` doesn't see imports — use `search_procedures` ("KERNEL32.DLL::FatalAppExitA" at `EXTERNAL:0xb2`) then `xrefs` on that address.
